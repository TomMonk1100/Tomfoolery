Explain it like I'm 5

Imagine a maze where you can never walk in a circle, and no corner is ever walled off from the rest. Then between any two spots there is exactly one route — never zero, never two. A maze like that is secretly a tree wearing walls: the passages are the branches, and there is only ever one way through.

Why you're looking at this

I built three different maze-makers — a burrowing one, a wall-merging one, and a growing one — and I wanted to check whether they all keep the same promise. They do, and the page checks it live, every time: count the passages, and a perfect maze always has exactly one fewer passage than it has cells, with every cell reachable. That is not a style choice. It is the tree showing through. Press solve and the gold line is the one route — the only one there is.

the one fact that runs the page

A grid of cells joined by passages is a graph. A graph with no loops, where everything is connected, is a tree — and a tree on n cells always has exactly n − 1 edges. So a perfect maze is checkable in one count: passages = cells − 1, and every cell reachable from the entrance. Both halves are run on the maze above, every time it changes. If either failed, the line would say so in pink.

The three generators reach the same tree by different roads. backtracker burrows: it walks into unvisited cells and backs out of dead ends, which leaves long winding corridors. kruskal shuffles every possible wall, then knocks through the ones that join two separate regions — the maze assembles everywhere at once. prim grows: it keeps a frontier of walls next to the maze built so far and keeps annexing one at random. Same promise, three different handwritings.

notes

  • The generators, the solver, and the checker on this page are the same code as the tested node core (647 checks, all passing) — ported inline, not rewritten. Same seed, same size, same generator: the page and the core produce the identical maze.
  • The solver is breadth-first search from the top-left cell to the bottom-right. In a perfect maze its answer is not just the shortest path — it is the only simple path, so nothing faster or cleverer could find a different one.
  • Honest caveat: "perfect" is a property of the passage graph, not a promise that a maze feels hard. Prim mazes at these sizes tend to feel bushier and backtracker mazes windier, but I have not measured difficulty here — only structure. The count is the claim; the feel is yours to judge.
  • The seed box is real: the generators run on a seeded mulberry32 generator, so any maze here can be reproduced exactly by re-entering its seed.
